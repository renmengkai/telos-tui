# System Core Behaviors

## 设计哲学

1. **声明式配置 > 硬编码**: 所有用户可见的行为（意图匹配、交互流程、提示文本）都应在 Markdown 文件中声明，运行时加载。
2. **文件即数据库**: 不使用外部数据库，所有持久化通过 Markdown + YAML frontmatter + JSON 完成。
3. **渐进增强**: 内核文件缺失时，系统应优雅降级到内置默认值。

## 内核加载顺序

系统启动时按以下顺序加载内核定义：

1. `skills/_kernel/intent-matching.md` — 意图匹配规则
2. `skills/_kernel/interaction.md` — 交互协议定义
3. `skills/_kernel/system.md` — 系统行为（本文件）

如果内核文件缺失，使用编译时内置的默认值。

## 降级策略

| 场景 | 行为 |
|------|------|
| 内核目录不存在 | 使用内置默认值，记录警告日志 |
| 单个内核文件缺失 | 该项使用内置默认值，其他正常加载 |
| 内核文件解析失败 | 该项使用内置默认值，记录错误日志 |
| 规则格式错误 | 跳过该规则，继续加载其他规则 |

## 运行时规则热重载

- 系统启动时加载一次内核配置
- 未来可考虑: 按 `Ctrl+R` 重新加载内核配置（无需重启）
- Skill 的扫描在每次操作后自动刷新

## 版本兼容性

内核文件版本格式：`v{major}.{minor}.{patch}`

- **Major 版本变更**: 可能破坏现有解析逻辑，需要更新代码
- **Minor 版本变更**: 新增字段，旧代码应忽略未知字段
- **Patch 版本变更**: 仅文本或规则内容变更，无需代码改动

当前系统支持的内核版本: `0.1.x`

## 扩展点

### 新增动作类型

如需新增系统动作：

1. 在 `intent-matching.md` 中添加新的动作章节
2. 在 Rust 代码的 `Action` enum 中新增对应变体
3. 在 `app.rs` 的 `handle_action` 中实现处理逻辑
4. 在 `interaction.md` 中定义相关的确认流程（如需要）

### 自定义确认行为

如需为某个动作添加确认流程：

1. 在 `intent-matching.md` 中该动作下添加 `确认提示` 和 `取消提示`
2. 系统会自动将模糊匹配转换为确认流程

## 配置优先级

配置加载优先级（从高到低）：

1. 运行时环境变量（`TELOS_*`）
2. `telos.toml` 配置文件
3. `~/.config/telos/config.toml`
4. 内核 skill 定义（`skills/_kernel/*.md`）
5. 编译时内置默认值

## 重要约束

- **不要**在内核文件中硬编码 API 密钥或敏感信息
- **不要**在内核文件中引用外部网络资源（保持离线可用）
- **保持**内核文件的人类可读性，这是用户可编辑的配置
- **保持**向后兼容，新版本的系统应能读取旧版本的内核文件

## 内置默认值备份

系统编译时包含一套完整的默认规则，确保即使内核文件全部丢失，系统仍可正常运行。
